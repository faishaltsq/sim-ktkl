## HIGH — Hard Gate

### 1. Em dash in user-facing copy (R-02)

Two occurrences, both in `templates/base.html`:

- **Line 633** — demo banner: `Mode Demo — Akun ini hanya bisa melihat data.`
- **Line 10** of `templates/nakes/nakes_list.html`: `Anggota Komite KTKL — Data STR, SIP & Status Kredensial Aktif`

Em dashes are a recognizable AI-writing tell. Replace with a comma, colon, or restructure the sentence.

**Fix:** `Mode Demo, akun ini hanya bisa melihat data.` and `Anggota Komite KTKL: Data STR, SIP & Status Kredensial Aktif`.

---

### 2. Demo credentials exposed in page source (R-36 / R-38)

`templates/accounts/login.html` hardcodes the demo account in hidden inputs:

```html
<input type="hidden" name="username" value="demo">
<input type="hidden" name="password" value="demo123">
```

Anyone viewing page source gets working credentials. The account is read-only, so the blast radius is limited to data exposure, but it is still a real security claim being undermined by the implementation. The "Read Only" badge next to the button also implies a restriction the source code contradicts.

**Fix options:** (a) replace the hidden-credential form with a server-side one-time demo token endpoint; (b) keep the button but have the view issue a short-lived session after a rate-limited request, so no static password ships to the browser.

---

### 3. No visible focus state defined (R-32)

`templates/base.html` sets `outline: none` on `.form-control:focus` and `.form-select:focus` and replaces it with a `box-shadow` ring. Bootstrap's default focus ring is suppressed on those controls, and no `:focus-visible` rule is defined anywhere in the templates. Keyboard users get no indicator on text inputs and selects.

**Fix:** add a `:focus-visible` rule for interactive elements, or keep the box-shadow but ensure it meets 3:1 contrast against the adjacent background (the current `rgba(2, 132, 199, 0.15)` ring on white is roughly 1.4:1, too weak).

## MEDIUM — Purpose-Gate

### 4. Glassmorphism dose exceeds cap (R-10)

`templates/nakes/dashboard.html` line 43 applies `backdrop-filter: blur(10px)` to `.hero-stat-card`. There are **four** of these cards rendered simultaneously inside the dashboard hero. The rule caps blur at 1-2 elements and forbids it on cards.

The blur serves no stated purpose here: the cards sit on a dark gradient, and the translucent white fill already reads as layered without the blur. The visual difference is negligible.

**Fix:** remove `backdrop-filter` from `.hero-stat-card`; keep the translucent fill and border.

---

### 5. Three-stop gradient as the hero background (R-01)

`templates/nakes/dashboard.html` line 11:

```css
background: linear-gradient(135deg, #0A1628 0%, #082433 50%, #063C47 100%);
```

A three-stop gradient covering the entire hero. The stops are all dark blue-teal and close in value, so the gradient reads as noise rather than hierarchy. It is decoration without a stated purpose.

**Fix:** flatten to a single solid `#0A1628`, or keep two stops maximum with a written hierarchy reason.

---

### 6. Uppercase + wide tracking used as default label styling (R-06)

Uppercase labels with letter-spacing appear in many places without a written brand-character reason:

- `templates/base.html` lines 112, 125, 383 (brand, nav sections, table headers)
- `templates/accounts/login.html` line 49 (`letter-spacing: 0.1em` on the brand badge)
- `templates/nakes/dashboard.html` lines 74, 155
- `templates/nakes/mutu_list.html` lines 19, 25, 31
- `templates/nakes/etik/sidang_calendar.html` lines 64, 73
- `templates/nakes/sekretariat/agenda_calendar.html` lines 31, 34
- `templates/admin/base.html` line 167

Table headers and stat labels in uppercase small caps are a common AI-dashboard pattern. The `0.1em` tracking on the login badge is the most extreme case.

**Fix:** either commit to uppercase micro-labels as a deliberate identity motif with the reason written down, or drop uppercase on table headers and stat labels and use sentence case with weight contrast instead.

---

### 7. JetBrains Mono loaded but effectively unused (R-06 / C-1)

`templates/base.html` line 14 loads `JetBrains Mono` from Google Fonts and applies it to `code, .font-mono`. A grep of the templates shows no `.font-mono` class usage and no `<code>` elements in the authored templates. The font is fetched on every page load for nothing.

**Fix:** remove the `JetBrains Mono` entry from the Google Fonts request and the `code, .font-mono` rule, or use it deliberately somewhere.

---

### 8. Inter + Plus Jakarta Sans is the default AI sans pairing (R-06)

`templates/base.html` line 14 loads `Inter` for body and `Plus Jakarta Sans` for headings. Both are among the most common AI default picks. The design would be more distinctive with a pairing chosen for this product's character (an institutional healthcare system).

**Fix:** pick a typeface for a reason tied to the product and write the reason down. This is a suggestion, not a defect: the pairing is readable and consistent.

---

### 9. Gradient on the demo banner and modal header (R-01)

Two gradients in `templates/base.html`:

- **Line 632** — demo banner: `linear-gradient(90deg,#F59E0B,#D97706)`
- **Line 659** — readonly modal header: `linear-gradient(135deg,#F59E0B,#D97706)`

Both are amber-to-amber. The gradient adds nothing over a solid `#D97706` and reads as decoration.

**Fix:** use solid `#D97706` for both.

---

### 10. Login brand panel gradient and decorative circles (R-01 / R-07)

`templates/accounts/login.html`:

- Line 16: `linear-gradient(135deg, #0F1923 0%, #0C7C84 100%)` on the full brand panel
- Lines 21-32: two large translucent circles via `::before` and `::after` at 2-3% opacity

The circles are invisible at that opacity on most displays; they are decoration with no perceivable purpose. The gradient is a two-stop dark-to-teal that does establish brand mood, so it can stay if the reason is written down.

**Fix:** remove the `::before`/`::after` circles. Keep the gradient with a written reason, or flatten it.

## LOW — Quality Locks

### 11. Uniform section rhythm across pages (R-05)

Most list pages follow the same internal pattern: `page-header-box` → filter card → table card. `dashboard.html`, `nakes_list.html`, `mutu_list.html`, `oppe_list.html`, and the etik/sekretariat list pages all open with the same header strip and card structure.

This is defensible for an internal admin tool (consistency aids scanning), but it means RHYTHM is effectively 1 and that should be a declared choice, not an accident.

**Fix:** declare the dials in a `DESIGN.md` and state that RHYTHM 1 is deliberate for an operational tool.

---

### 12. Pill-shaped badges everywhere (R-11)

`templates/base.html` line 395 sets `border-radius: 9999px` on `.badge`, and every status badge uses it. Buttons and cards use the `--radius` scale correctly, so radius variation exists between component types. The badge pill is consistent and functional (status chips), so this is minor.

**Fix:** none required if the pill badge is declared as the status-chip motif.

---

### 13. Card hover elevation on every card (R-12)

`templates/base.html` line 300: `.card:hover { box-shadow: var(--shadow-md); }` applies to every card on every page. On pages with many cards (dashboard, list pages), the whole surface lifts on hover, which flattens hierarchy instead of marking elevation.

**Fix:** restrict hover elevation to interactive cards only (those containing a primary link or action), or remove it.

---

### 14. No DESIGN.md, so no declared dials (R-37)

The project has no `DESIGN.md` and no entry-file pointer (`AGENTS.md`, `CLAUDE.md`). Design decisions are real and mostly purposeful, but none of the reasons are written down, which is what R-31 requires.

**Fix:** create a `DESIGN.md` capturing identity, palette, typography, and the three dials. This also makes future work faster.

---

### 15. antislop not installed in the project entry file

No `AGENTS.md` / `CLAUDE.md` exists, so antislop is not routed for future sessions. The core filter is active in this session only.

**Fix (optional):** create `AGENTS.md` with the antislop pointer block so the rules persist.
